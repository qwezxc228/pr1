## Собственный проект

Тема проекта: Каталог игр

Главный класс: Game

Почему этот объект нужен программе:
Класс Game позволяет хранить информацию о видеоиграх в одном месте, что удобно для создания каталога или библиотеки игр.

Какие данные хранит объект:

- Название (Title)
- Жанр (Genre)
- Год выхода (ReleaseYear)
- Рейтинг (Rating)
- Часы игры (HoursPlayed)

Какие значения задаются через конструктор:
Название, жанр и год выхода передаются при создании объекта, так как это основные и неизменные данные игры.

Какие значения можно задавать автоматически:
Рейтинг задается автоматически как 0.0. При добавлении игры в каталог у нее еще нет оценок от пользователей. Часы игры также начинаются с 0.

Какое значение я решил задавать автоматически и почему?
Я решил автоматически задавать рейтинг (0.0), так как при первом добавлении игры в каталог она еще не имеет оценок. Это избавляет от необходимости каждый раз передавать 0.0 в конструктор.

## Практическая работа №2

### Пять методов класса Hero:
1. `TakeDamage(int damage)` — уменьшает здоровье, защищает от отрицательного урона и не дает опустить здоровье ниже нуля.
2. `Heal(int amount)` — восстанавливает здоровье, игнорирует отрицательное лечение.
3. `GainExperience(int amount)` — увеличивает опыт героя.
4. `IsAlive()` — возвращает `true`, если здоровье больше нуля, иначе `false`.
5. `GetInfo()` — возвращает строку с информацией о герое.

### Как проверили недопустимый урон:
Вызвали `yaroslav.TakeDamage(-20)`. Здоровье Ярослава осталось 75, так как метод содержит проверку `if (damage <= 0) return;`.

### Итоговые показатели:
- **Ярослав:** здоровье 85, опыт 65.
- **Анастасия:** здоровье 60, опыт 0.
- **Артём:** здоровье 0, опыт 0.

### Ответы на вопросы (этап 11):
1. **Почему при `yaroslav.TakeDamage(25);` не меняется здоровье Артёма?** Метод экземпляра работает с полями того объекта, у которого он вызван (получателя вызова). Вызов происходит через `yaroslav`, поэтому меняется его поле `Health`.
2. **Чем отличаются `return;` в `TakeDamage` и `return Health > 0;` в `IsAlive`?** `return;` без значения используется в `void` методах для досрочного выхода. `return Health > 0;` возвращает конкретное значение типа `bool` (истина или ложь).
3. **Как получить строку о герое, не печатая её сразу?** Нужно вызвать метод `GetInfo()`, который возвращает строку. Мы сохранили её в переменную `info` (`string info = yaroslav.GetInfo();`), а напечатали позже с помощью `Console.WriteLine(info);`.

  - *Что делает:* Увеличивает количество сыгранных часов в игре. Отклоняет отрицательные значения.

## Практическая работа №3

### Защита состояния Hero

**Почему методы ПР №2 не защищали от прямой записи в поле:**
Внешний код из `Program.cs` мог напрямую обратиться к открытому полю `Health` и присвоить ему любое значение (например, `-100`), не вызывая методы `TakeDamage` или `Heal`. Методы защищали только те действия, которые проходили через них.

**Чем отличаются get, set и private set:**
- `get` — позволяет читать значение свойства.
- `set` — позволяет записывать значение свойства.
- `private set` — позволяет записывать значение только коду, который находится внутри самого класса. Извне запись запрещена.

**Где проверяется начальное здоровье:**
Начальное здоровье и предел проверяются в конструкторе `Hero(string name, int health)`. Если здоровье больше 200, оно и предел уменьшаются до 200. Если здоровье меньше или равно 0, предел становится 100, а текущее здоровье — 0.

**Как Heal сохраняет границу MaxHealth:**
Метод `Heal` сначала проверяет, не превышает ли лечение недостающее здоровье (`MaxHealth - Health`). Если превышает, здоровье сразу ставится на `MaxHealth`. Иначе прибавляется обычным способом.

**Как Name использует поле _name и значение value:**
Свойство `Name` при записи получает значение в переменную `value`. Проверяет его на пустоту с помощью `string.IsNullOrWhiteSpace`. Если строка нормальная, она очищается от пробелов `value.Trim()` и сохраняется в закрытое поле `_name`.

**Почему в конструкторе используется Name = name:**
Это позволяет запустить `set` свойства `Name`, который проведет проверку и очистку имени. Если бы мы написали `_name = name`, проверка была бы обойдена внутри самого класса.

### Проверки

- **Конструктор:** `new Hero("   Александр   ", 150)` дал имя `[Александр]` (без пробелов) и здоровье `150/150`.
- **Конструктор:** `new Hero("Проверка", -100)` дал здоровье `0/100`.
- **Урон и лечение:** после `TakeDamage(10)` и `Heal(10)` здоровье осталось `150`.
- **Имя:** исходная строка `"   Александр   "` превратилась в `"Александр"`.
- **Запрет записи:** `alexander.Health = -100;` не компилируется (ошибка `CS0272`), так как `set` закрыт.

### Исправление ошибок

1. **Ошибка 1:** `public int Health { get; set; }` — свойство было слишком открытым. Исправлено на `public int Health { get; private set; }`. Проверка: попытка присвоения извне вызывает ошибку компиляции.
2. **Ошибка 2:** `value.Trim(); _name = value;` — результат `Trim()` не сохранялся. Исправлено на `_name = value.Trim();`. Проверка: имя `[   Александр   ]` стало `[Александр]`.

### ПР №3. Инкапсуляция собственного класса (Game)

**Класс и его назначение:** `Game` — хранит информацию об играх в каталоге.
**Какие данные защищены и почему:** `HoursPlayed` защищено от отрицательных значений, чтобы счетчик часов не уменьшался. `Title` защищено от пустых строк и лишних пробелов.
**Какие свойства имеют private set:** `Title`, `Genre`, `ReleaseYear`, `Rating`, `HoursPlayed`.
**Какое свойство использует закрытое поле:** `Title` использует `_title`.
**Что проверяют конструктор и методы:** конструктор проверяет и очищает название, метод `AddHoursPlayed` игнорирует отрицательные значения.
**Проверки двух объектов:** `game1` (The Witcher 3) накопил 15 часов, `game2` (Minecraft) остался с 0 часов — изменение первого не затронуло второй.
